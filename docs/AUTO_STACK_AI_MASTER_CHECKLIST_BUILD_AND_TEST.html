01 AI-INFRA-01 Monorepo / Dual Web App Setup Khởi tạo kiến trúc thống nhất gồm Backend API Server + 02 Web App dùng chung theo vai trò (Backoffice App cho Admin/HR/Store/Finance/MKT và Employee Mobile Web App cho Thử việc/Chính thức); đồng bộ biến môi trường và version build. Chạy health-check endpoint `/api/health` và kiểm tra version hiển thị khớp nhau trên cả 02 Web App và Backend.
02 AI-INFRA-02 Auth, Hash & Session Guard Triển khai đăng nhập, băm mật khẩu/PIN bằng bcrypt/argon2 (tuyệt đối không lưu mật khẩu/PIN thô trên Google Sheets); quản lý phiên (JWT + Session Store) hỗ trợ thu hồi phiên tức thời. Kiểm tra dữ liệu trên Google Sheets không chứa plaintext password/PIN; thử dùng token của phiên đã bị thu hồi gọi API -> phải trả về `401 Unauthorized`.
03 AI-INFRA-03 RBAC & branchScope Middleware Xây dựng Backend Guard xác thực `ROLE`, `permissions` và `branchScope` trên 100% API routes. Chặn tuyệt đối truy cập chéo chi nhánh (Store), chéo nhân viên (Employee) và chéo vai trò (MKT không truy cập lương/GPS/ảnh). Automated API Test: Dùng token Store CN1 gọi dữ liệu CN2 -> `403`; dùng token NV A gọi phiếu lương NV B -> `403`; dùng token MKT gọi API lương/GPS -> `403`.
04 AI-INFRA-04 Google Sheets Sync Engine & Write Queue Triển khai lớp đọc/ghi Google Sheets có hàng đợi (Write Queue), cơ chế retry khi gặp lỗi quota/timeout, gắn cờ `NEEDS_RECONCILIATION` khi chưa đồng bộ xong. Chỉ trả kết quả thành công về UI sau khi Sheets xác nhận đã ghi. Giả lập lỗi timeout/quota từ Google Sheets API -> Backend không được báo `200 OK` ảo hay phát Socket thành công giả; bản ghi phải chuyển vào trạng thái `NEEDS_RECONCILIATION`.
05 AI-INFRA-05 Socket.IO Realtime & forceLogout Tích hợp Socket.IO có xác thực token và phân room theo `role`, `branchScope`, `employee_id`. Phát sự kiện `forceLogout` khi khóa/thu hồi tài khoản, và phát sự kiện realtime cho chấm công, đổi ca, nghỉ khẩn, kích hoạt TK. Mở phiên đăng nhập nhân viên trên trình duyệt -> Admin gọi API thu hồi TK -> Client nhận event `forceLogout` và đăng xuất ngay lập tức trong < 1 giây.
06 AI-INFRA-06 Immutable Audit Log Service Xây dựng dịch vụ ghi Audit Log tự động (append-only) với đầy đủ các trường: `actor`, `action`, `entity`, `before_data`, `after_data`, `timestamp`, `ip/trace` cho mọi thao tác kích hoạt TK, phân quyền, cấu hình, lịch, công, lương. Thực hiện thay đổi quyền hoặc duyệt công -> Kiểm tra bảng Audit Log ghi nhận đúng dữ liệu trước/sau; xác nhận không có API nào cho phép sửa/xóa dòng Audit Log.
07 AI-INFRA-07 Attendance Photo Storage & GPS Verifier Triển khai module lưu trữ ảnh điểm danh (`photo-disk.store.ts` kết hợp đồng bộ/backup Google Drive theo cấu hình), bảo vệ URL ảnh bằng middleware phân quyền; hàm tính khoảng cách Haversine kiểm tra bán kính GPS và `accuracy`. Gửi ảnh base64/multipart kèm tọa độ GPS trong/ngoài bán kính -> Xác nhận tính đúng khoảng cách (m), lưu ảnh an toàn và chặn truy cập ảnh trái phép từ MKT hoặc chi nhánh khác.
08 AI-INFRA-08 Immutable Attendance & Adjustment Engine Thiết kế cấu trúc lưu trữ sự kiện chấm công gốc (`raw attendance events`) ở chế độ bất biến (không UPDATE/DELETE). Mọi bổ sung/điều chỉnh công phải tạo bản ghi `adjustment` liên kết `event_id` hoặc `shift_assignment_id` kèm lý do và người duyệt. Duyệt 1 phiếu bổ sung công -> Kiểm tra DB/Sheets: bản ghi chấm công gốc không bị thay đổi, xuất hiện bản ghi `adjustment` mới và dòng Audit Log tương ứng.
09 AI-INFRA-09 Server-side TEST Countdown & Auto-Submit Xây dựng bộ đếm thời gian làm bài TEST quản lý tại Server (`started_at`, `expires_at` từ Server clock), tự động thu bài và chấm điểm khi hết giờ theo ngưỡng đạt đã được phê duyệt. Bắt đầu bài thi -> Thử đổi đồng hồ hệ thống trên máy client -> Thời gian còn lại vẫn tính chuẩn theo Server; khi hết giờ hệ thống tự động khóa và nộp bài.
10 AI-INFRA-10 Payroll State Machine & Snapshot Engine Triển khai máy trạng thái kỳ lương 5 bước (`DRAFT -> RECONCILE -> APPROVED -> PUBLISHED -> PAID`). Khi chốt lương tạo `Snapshot` đóng băng dữ liệu công và đơn giá (`effective rate`); khóa sửa đè phiếu lương đã `PUBLISHED` (chỉ cho phép tạo `revision`/`adjustment`). Chốt kỳ lương sang `PUBLISHED` -> Thử thay đổi đơn giá lương hoặc công nguồn -> Phiếu lương đã snapshot không bị biến động số tiền; thử gọi API sửa đè phiếu đã `PUBLISHED` -> bị chặn.
